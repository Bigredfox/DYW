How the pieces connect

You type into React's screens. A shared storage module writes unfinished answers as drafts and commits completed entries when you save. History reads the same saved data.

Storage belongs to this browser and app address. Reopening keeps it; clearing site data removes it. There is no device sync. Use one active tab for this PoC.

What gets remembered?

Saved in the browser

  • Monday of the first-use week
  • One saved entry per calendar date
  • One unfinished draft per date
  • Six answers and draft progress
  • Created/updated timestamps

Only while the app is open

  • Current screen and open menu
  • Overwrite dialog
  • Transition and error messages
  • Latest text if a storage write fails

Display name and prompt labels live in code.

One JSON snapshot under daily-work-log:v1 keeps commits consistent. Dates use calendar strings; writing timestamps do not change which day or week owns a log.

Weeks follow the calendar

First use on Friday

That Monday–Sunday period is Week 1. The following Monday begins Week 2. Empty weeks still count.

Catch up before first use

Proposed default: label earlier groups with their date range and “Before first use.” Keep Week 1 anchored to the actual first-use week.

Calendar helpers handle year changes and daylight-saving boundaries without using elapsed local hours to count weeks.

How we know it works

Focused automated checks

Week boundaries, catch-up grouping, protected replacement, write failure, and removing only the completed draft.

Acceptance walkthrough

Six prompts including blanks, review corrections, reload/resume, Edit/Start Over, overwrite cancellation, keyboard use, reduced motion, and empty history.

Failure handling

A failed write retains answers in memory, reports that persistence failed, and offers retry. It does not show success or alter the durable saved snapshot. Warn that unpersisted text will not survive closing the tab.

Malformed stored data is reported without automatically resetting or overwriting it.

Enter two or three fictional sample logs through the real catch-up flow for the demo. Normal first use starts empty; sample history is identified as such.
